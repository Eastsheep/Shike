# 食刻熱量日記

手機用的飲控紀錄網頁：拍照或文字描述交給 DeepSeek 估算熱量，也能手動記錄。紀錄存在你自己的私人 GitHub repo。

## 架構

| 部分 | 放哪裡 |
|---|---|
| 網頁（這個 repo） | GitHub Pages，公開 |
| 飲食紀錄 | 另一個**私人** repo（例如 `shike-data`），`data/YYYY-MM.json` 每月一個檔（飲食和活動消耗），`profile.json` 存目標 |
| 我的食物 | 同一個私人 repo 的 `myfoods.json`（自己存的常吃食物，含照片） |
| 食物照片 | 同一個私人 repo 的 `photos/YYYY-MM/`，壓縮成約 1080px 的 JPEG；手機上也會留一份，離線時先存著、連線後再上傳 |
| AI 估算 | DeepSeek API，模型 `deepseek-flash` |

GitHub token 和 DeepSeek API key 只存在手機瀏覽器的 localStorage，不會寫進這個 repo。

## 設定步驟

1. **網頁 repo**：建立公開 repo（例如 `shike`），上傳 `index.html`、`foods.js`、`manifest.webmanifest`、`icon.svg`、`README.md`。
   到 Settings → Pages → Branch 選 `main`、資料夾 `/ (root)` → Save。網址會是 `https://<帳號>.github.io/shike/`。
2. **資料 repo**：建立**私人** repo `shike-data`，勾選 *Add a README file*。
3. **GitHub token**：Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token。
   - Repository access：Only select repositories → `shike-data`
   - Permissions → Repository permissions → Contents：Read and write
   - 有效期限自己決定，到期後在 App 設定裡換新的
4. **DeepSeek API key**：到 platform.deepseek.com 建立 API key，儲值少量金額即可。
5. 手機打開網址 → 右上角齒輪 → 填入帳號、`shike-data`、token、DeepSeek key → 測試連線 → 儲存。
6. 加入主畫面：iPhone 用 Safari 的「分享 → 加入主畫面」；Android 用 Chrome 選單的「加到主畫面」。

## 食物清單（foods.js）

「手動」裡的台灣常見食物清單放在 `foods.js`，每一行是一種食物：

```
["白飯", "主食", "g", "碗", 200, 366, 6.2, 82, 0.6],
```

依序是：名稱、類別、計量方式（固體 `"g"`、液體 `"ml"`）、常見份量名稱、該份量是幾 g 或幾 ml、該份量的熱量 kcal、蛋白質 g、碳水 g、脂肪 g。

選了食物之後，份量可以用該食物的常見份量（例如「碗」），也可以改用 g／oz／台兩（固體）或 ml／cc／fl oz／量杯（液體），熱量會自動換算。
要新增食物，在 GitHub 上編輯 `foods.js`，照同樣格式加一行即可（注意逗號）。數值是一般份量的估計值，實際依店家和做法而異。

## 從 Apple 健康 App 帶入活動消耗

網頁無法直接讀取健康 App，所以用 iPhone 內建的「捷徑」App 讀取數字，再用網址傳給食刻。

### 1. 在食刻開啟動態目標

目標 → 勾選「把健康 App 的活動消耗加到當天的熱量目標」→ 選擇計入比例（建議 75%）→ 儲存。
開啟後，熱量目標代表「沒有額外活動」的基礎目標；用計算機時會自動以「久坐」計算。

### 2. 建立捷徑「食刻健康」

捷徑 App →「+」新增捷徑，名稱改成 **食刻健康**（名稱要完全相同，App 裡的按鈕才找得到它）。

這個捷徑可以讀「任何一天」：從食刻裡按按鈕執行時，食刻會把你正在看的日期傳給它；直接在捷徑 App 點、或用自動化執行時，沒有傳日期，就讀今天。

先設定接收輸入：點捷徑最上方的「ⓘ」或「接收…輸入」，讓它接收 **文字**；「如果沒有輸入」選 **繼續**。

接著依序加入（「設定變數」是幫數字取名字，之後插入時不會選錯）：

1. **如果**：「捷徑輸入」→ 條件選「有任何值」
2. （在「如果」裡面）**從輸入取得日期**：輸入是「捷徑輸入」
3. （在「如果」裡面）**設定變數**：名稱 **日期**
4. （在「否則」裡面）**日期**：選「目前日期」
5. （在「否則」裡面）**設定變數**：名稱 **日期**
6. （「結束如果」之後）**調整日期**：日期用變數 **日期**，選「取得一天的開始」
7. **設定變數**：名稱 **開始**
8. **調整日期**：日期用變數 **開始**，選「加」**1 天**
9. **設定變數**：名稱 **結束**
10. **尋找健康樣本**：類型選 **動態能量**（英文版叫 Active Energy），篩選條件「開始日期」選「**介於**」，填變數 **開始** 和 **結束**
11. **計算統計資料**：選「總和」
12. **設定變數**：名稱 **活動**
13. **尋找健康樣本**：類型選 **步數**，篩選條件一樣是「開始日期 介於 開始 和 結束」
14. **計算統計資料**：選「總和」
15. **設定變數**：名稱 **步數**
16. **格式化日期**：日期用變數 **開始**，日期格式選「自訂」，填 `yyyy-MM-dd`，時間格式選「無」
17. **文字**，內容如下（中括號的部分用變數插入，中間不要有空格）：
    `https://eastsheep.github.io/Shike/#d=[格式化的日期]&a=[活動]&s=[步數]`
18. **打開 URL**：輸入是上一步的「文字」

不要選「靜態能量」，那是基礎代謝，已經算在基礎目標裡了。
第一次執行時，捷徑會要求讀取健康資料的權限，請允許。

### 3. 執行

- 在食刻切到想要的那一天 → 點「活動消耗」那一列 →「從健康 App 帶入…的數字」，捷徑就會讀那一天的資料。
- 直接在捷徑 App 點它，則是讀今天。
- 想每天自動執行：捷徑 App →「自動化」→「+」→「特定時間」，例如每天 21:30 →「立即執行」→ 選「食刻健康」。手機鎖定時打不開網址，所以時間請選你通常在用手機的時段。

### 注意

- iPhone 從捷徑打開網址時，會用 **Safari** 開啟，而不是主畫面上的食刻；兩者的設定是分開存的。所以在 Safari 裡也要到設定貼一次 GitHub token，數字才會同步到 GitHub，主畫面的食刻下次打開時就會讀到。
- 讀今天時，捷徑傳的是「到執行當下為止」的累計數字，同一天多跑幾次會以最後一次為準；讀過去的日子則是那天的完整數字。
- 也可以點「活動消耗」那一列手動輸入數字。

## 注意

- 換手機或清除瀏覽器資料後，要重新貼 token 和 key。紀錄本身在 GitHub 上，不會不見。
- token 外流的話，到 GitHub 把它撤銷（Revoke）再建一個新的。
- AI 估算只是參考，加入前可以修改數字。
